# github

Своего автора у мода нет: это порт нашей копии `gitlab` (сам он из https://github.com/rem-aster/herdr-gitlab, коммит `dc4931a029f827c93632931a2e940a93b9a2da51`, лицензия MIT, текст в `LICENSE`). Отрисовка, меню, диалоги и правки workbench (прямые углы, сетка 32/14, без создания worktree и запуска агентов) взяты оттуда. Иконки Lucide, как у `gitlab`; `icons/github.svg` это иконка `github` из Lucide.

## Чем отличается от gitlab

- Данные идут через `gh`: GraphQL для списков, PR, ревью, тредов и merge, REST для Actions, файлов PR, комментариев и закрытия. `api.js` приводит ответы GitHub к той форме, в которой `gitlab` получал MR и пайплайны, поэтому отрисовка почти та же.
- Вместо пайплайна у ветки и PR показаны проверки последнего коммита: стадия на каждый workflow (или приложение), джоба на каждую проверку. Внизу список последних workflow runs, их джобы загружаются, когда строку раскрывают.
- Лог показывает `gh run view --job <id> --log` с вырезанным префиксом «джоба, шаг, время». GitHub отдаёт лог только после окончания run. У проверок не из Actions лога нет, клик открывает их страницу.
- Approve нельзя отозвать, как в GitLab: вместо этого «Dismiss approval», он требует прав на запись.
- Merge: способ (merge commit, squash, rebase) из разрешённых в репозитории, по умолчанию тот, что GitHub запомнил для тебя. Ветку после merge удаляет сам GitHub, если так настроен репозиторий, иначе панель удаляет её через REST. Вместо «merge when pipeline succeeds» включается auto-merge GitHub, если он разрешён в репозитории.
- `gh pr merge` не используется: с `--delete-branch` он трогает локальный репозиторий (удаляет ветку, переключает на базу), а панели репозиторий не меняют.
- Счётчика to-do нет, в меню проекта вместо него ссылка на запросы ревью.
- Хост: github.com, GitHub Enterprise, если `gh` на нём залогинен, и ssh-алиас с `github` в имени (например `github-work`), он считается github.com.
